# Super-Join

Super-Join compiles a nested data request — initially GraphQL — into a parameterized SQL artifact. It is a compiler, not a query runner: your application owns the database driver, connections, and execution. The main API is `superjoin` / `superjoin.graphql`: compile, run-your-driver-callback, hydrate — in one call.

## Guides

Two parallel guide series walk the same steps for the two ways of authoring model metadata:

- **[Decorator guide](guides/decorators/intro.md)** — *the preferred pattern*. Declare entities as TypeScript classes with `@Entity`, `@Field`, and `@Relation`; generate a `GraphQLModel` from them.
  - [Building a GraphQL server](guides/decorators/building-a-graphql-server.md)
  - [Filtering, pagination, and hooks](guides/decorators/filtering-pagination-hooks.md)
  - [Result shape and hydration](guides/decorators/result-shape-and-hydration.md)
- **[Core API guide](guides/core-api/intro.md)** — hand-author the serializable model objects for full control.
  - [Building a GraphQL server](guides/core-api/building-a-graphql-server.md)
  - [Filtering, pagination, and hooks](guides/core-api/filtering-pagination-hooks.md)
  - [Result shape and hydration](guides/core-api/result-shape-and-hydration.md)

Start with [Getting started](guides/getting-started.md) for install, the `superjoin` main API, and error basics.

## Examples

Runnable versions of both guides live in the repository:

- `examples/decorators-graphql-js` — TypeScript server using decorators + `superjoin.graphql` (`make example_decorators-graphql-js`).
- `examples/graphql-js` — plain JavaScript server with hand-authored metadata (`make example_graphql-js`).
