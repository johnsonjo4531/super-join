# Super-Join

Super-Join compiles a nested data request — initially GraphQL — into a parameterized SQL artifact. It is a compiler, not a query runner: your application owns the database driver, connections, and execution.

## Where to go

- [Getting started](guides/getting-started.md) — install, compile your first GraphQL query, handle errors.
- [Building a GraphQL server](guides/graphql-server.md) — a complete graphql-js server whose queries compile to SQL through Super-Join.
- [Filtering, pagination, and hooks](guides/filtering-and-hooks.md) — arguments as filters, ordering, hook API, fragments, error codes.
- [Result shape and hydration](guides/result-shape-and-hydration.md) — read the SQL artifact and regroup flattened rows into nested entities.
- [TypeScript decorators](guides/decorators.md) — declare model metadata with `@Entity`, `@Field`, `@Relation`, and generate a `GraphQLModel` from classes.
- TypeScript API reference — generated from TSDoc comments in `src-js/`; in this site it is the module hierarchy in the sidebar, on disk it is built into `api/`.
- Rust API reference — generated by `cargo doc` for `super-join-core` and `super-join-component`; built into `rust-api/index.html`.

## How these docs are updated

The APIs shown here always come from the current code signatures. See [ai-design-docs/user-facing-docs.md](../../ai-design-docs/user-facing-docs.md) for the update workflow; in short:

```sh
npm run docs   # rebuilds api/ (TypeScript) and rust-api/ (Rust)
```
