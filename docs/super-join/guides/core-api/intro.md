# Intro: why the core API

In this guide you author Super-Join's model metadata directly as plain serializable data and drive the compile → run → hydrate steps yourself. The alternative — declaring the same metadata with TypeScript decorators — is the [preferred pattern](../decorators/intro.md) for most TypeScript servers; read that first if you have a choice.

## What you choose by using the core API

- **Plain data, no tooling**: entities, fields, and relations are ordinary objects (`Model`), so metadata can be generated by introspection, loaded from a config file, or written in JavaScript with no build step and no `experimentalDecorators`.
- **Full control**: every id is yours to choose, the name→id bridging functions are explicit, and you see each pipeline step (`graphqlToSQL`, `compile`, your driver, `hydrate`) as its own call.
- **Same compiler, same artifacts**: nothing about the core API changes what the compiler does — generated decorator metadata is structurally identical to hand-authored metadata.

## A taste

```ts
import type { Model } from "super-join";

const model: Model = {
  entities: [
    {
      id: 0n,
      source: { components: ["users"] },          // FROM "users"
      fields: [
        { id: 0n, identifier: { components: ["id"] }, dataType: "int64", nullable: false, selectable: true },
        { id: 1n, identifier: { components: ["name"] }, dataType: "text", nullable: false, selectable: true },
      ],
      relations: [],
      identity: new BigUint64Array([0n]),         // primary key field ids
    },
  ],
};
```

and to run a request end to end:

```ts
import { compile, hydrate } from "super-join";

const { artifact } = await compile(request);
const rows = await db.query(artifact.sql, artifact.parameters.map(toDriverValue));
const entities = hydrate(rows, artifact);
```

`superjoin()` does the same three steps in one call if you prefer it; this guide shows them separately so each piece stays visible.
